DigiQuick 首筆數字債券發行：功能補充、改動與待確認事項

日期：2026-11-24｜版本：v3（精簡版）
  • 依據：digiquick-integration-guide-v0.6.md（Aegis 冷錢包 API 仍在規劃，尚未實作）、Digital_Asset_Risk_Assessment_Report.md，以及對 digiquick-api／admin／app 的唯讀核對。檔案路徑相對於各 repo。
  • 人日、工期與分階段估算見本檔的 git 歷史（v1 commit ff1fb49、v2 commit 723d937）。
定位：DigiQuick 是發行營運中樞，只處理簿記配售、身份合規、交割編排、登記、生命週期，以及送出結構化業務意圖給 Aegis。
不在範圍內：私鑰託管與簽名、鏈上執行（由 Aegis 負責）；資金收付（人工處理，DigiQuick 只記錄憑證）；合約開發（digiquick-contracts 和 TokenFactory 不動）；listener 鏈上掃描；既有 8 種資產；二級市場。
標記：Aegis 表示依賴 Aegis API 交付。

一、要新增的功能

1. 簿記配售

功能內容
發行（Offering）管理建立發行與條款；狀態機：草稿 → 開放認購 → 截簿 → 已分配 → 交割中 → 已發行 → 已贖回
訂單簿下單、修改、撤單、截簿，保留每次修改的紀錄；投資人在 APP 下單，或 OPS 在 admin 代下單
分配在系統內分配（也可匯入 CSV）；校驗合計等於發行量、不超過訂單量；雙人核准；發出分配通知
發行人訂單簿頁發行人在 APP 查看即時訂單簿、分配結果和持有人

2. 身份合規

功能內容
專業投資者認定紀錄記錄認定結果、證明文件和有效期
發行資格規則與合規閘門每檔發行設定資格（例如只限專業投資者、司法管轄區）；不合格者無法下單；合規通過才會進入 allowlist 意圖
Aegis 客戶與錢包申請 AegisKYC 通過後，自動送出發行人或投資人的客戶申請和錢包申請；記錄 clientId、walletId

3. 交割編排

功能內容
交割指示依分配結果產生每位投資人的付款指示（金額、帳戶、期限），在 APP 顯示
付款憑證錄入與覆核OPS 錄入到帳並上傳銀行回單，由另一人覆核
交割狀態機待付 → 已付已覆核 → 已送 mint 意圖 → 已交付；處理部分到帳、逾期和交割失敗
先款後券檢查付款未經覆核的投資人不會進入 mint 批次

4. 登記

功能內容
權威登記冊持有人登記冊，變更只追加不改寫，可重建任一時點的持有人
記錄日快照依付息和贖回日程產生快照
登記冊摘錄發行人和投資人可在 APP 查看或下載
鏡像比對 Aegis登記冊和 Aegis holders API、錢包餘額比對，產出差異報告

5. 生命週期

功能內容
付息結構化付息日程；計算固定利率應得金額，產出應得清單給付款代理；錄入付款完成憑證
到期贖回 Aegis本金付款確認後，送出 BATCH_BURN 意圖，並註銷登記冊
更正與轉讓 Aegis收到書面指示後，送出 BURN_AND_MINT 意圖，並更新登記冊
Aegis 後台事件回寫 Aegis暫停、凍結、強制轉移等事件透過 webhook 回寫登記冊，並發出告警

6. 結構化業務意圖（Aegis 整合層）

功能內容
Aegis client AegisRSA-PSS 簽章（path 含 query string）、限流、錯誤分類
意圖請求表每個意圖都綁定業務單號和唯一 referenceId；結果不明時不重用 referenceId；只接受 seq 遞增的狀態更新
webhook 接收 Aegis以 raw body 驗 HMAC；用 callbackId 去重；處理亂序；10 秒內回應
輪詢與漏收補償輪詢未到終態的請求；查詢失敗投遞並要求重送；逾時告警
發行編排 Aegis依序送出：條款、CMTAT 部署、6 個角色指派（一次一筆）、allowlist（每批最多 20 筆）、mint、burn
請求列表與人工補單admin 顯示 referenceId、狀態、txHash；在雙人核准下作廢並以新 referenceId 重送
Aegis mock server模擬 202、409、429、TIMEOUT、UNKNOWN、亂序和重複送達，供開發與測試使用

7. 平台共用

功能內容
雙人覆核分配核准、付款確認、mint 或 burn 觸發這三個動作，強制發起人和核准人不同，並寫入稽核日誌
投資人 APP 頁我的訂單、分配、付款指示與狀態、持倉、txHash、登記冊摘錄
admin 營運主控台發行、訂單簿、分配、付款覆核、核准佇列、例外佇列、對帳結果
金鑰管理與稽核Aegis API 私鑰和 webhook secret 放進 KMS 或 Secrets Manager；匯出稽核日誌；保護個資
監控告警webhook 失敗、請求久未到終態、CFX 餘額不足、登記冊比對有差異

三、待確認事項

DigiQuick

  1. 首發投資人是法人還是自然人？大約多少人？（若有自然人，註冊和 Aegis 申請都要另開個人分支）
  2. DigiQuick 自己擔任簿記管理人，還是只提供系統給安排行使用？這會影響訂單簿的權限模型。
  3. 專業投資者認定的標準和證明文件是什麼？KYC 要多久複核一次？
  4. 收款帳戶屬於誰？交付時限是 T+幾天？部分到帳和逾期怎麼處理？
  5. 首發是否允許轉讓或提前贖回？
  6. incorporationNo 能否沿用註冊時填的 Business Tax ID？
  7. 雙人覆核還要涵蓋哪些動作？OPS 和合規的人力有多少？
  8. 目標發行日期是？

Aegis

  1. 何時提供 SPEC.md（deployment body、6 個角色、CMTAT 版本與審計、decimals）？
  2. dev、stg、主網的確切交付日期，以及每筆人工審核的 SLA 和吞吐量。
  3. 法人投資人應該用哪一種 client kind？（目前 INVESTOR 只收個人欄位）
  4. 同一家公司既是發行人也是投資人時，要開兩個 client 嗎？
  5. 客戶申請能否自動核准？
  6. CFX gas 由誰支付、誰補充？
  7. 主網 KYT 的時程（決定何時能開放外部地址）。
  8. Aegis onboarding 的 KYC 結果能否直接作為投資人 KYC 的依據？
  9. Aegis 後台的凍結、強制轉移等操作，回寫 DigiQuick 登記冊時的順序和確認機制怎麼定？

律師、付款代理及其他

  1. DigiQuick 擔任登記處和簿記方，是否需要委任或牌照？如果不能擔任登記處，登記冊要降級為鏡像。
  2. 條款何時定稿？代幣和登記冊的法律關係？強制轉移的依據？ISIN 何時取得？
  3. 付款代理到帳清單的格式？付息和贖回的作業時限？
  4. DigiQuick 計算的應得金額和付款代理不一致時，以哪一方為準？
  5. 是否要做滲透測試（OZ R02.4）？由誰做、排在何時？
本文件為範圍整理，不構成承諾。待確認事項有答案後，功能清單可能要再調整。
