範圍和原估算相同：bond 首發，對象是發行方與機構投資人，M0–M12；個人投資人（第二階段）與其他 8 種資產不在範圍內。「全程 AI 開發」指程式碼、測試、mock server、頁面由 AI agent（如 Claude Code）產出，人負責拆任務、定規則、審查、驗收與對外協調。

AI 不會讓所有工作一樣快。程式碼產生不再是瓶頸，瓶頸變成人審查的速度、未定的業務規則，以及 Aegis 的環境與審核。

現況：影響 AI 開發速度的兩件事

  • 沒有任何測試：digiquick-api/apps/main/test 目前沒有 *.spec.ts。AI 改完程式無法自己驗證，也無法確認其他 8 種資產沒被改壞，所以 M0 修 jest 一定要最先做。
  • codegen 指向遠端：admin 和 APP 的 codegen.yml 讀的是已部署的 dev API schema。後端新寫的 schema 還沒部署前，前端拿不到型別，前後端無法並行；要改成可讀本機 schema 或 schema 檔。

程式規模（不含 node_modules、codegen 產物、migration）：api 約 2.9 萬行、admin 約 1.4 萬行、APP 約 1.9 萬行，AI 讀得完整體結構，既有 pattern（每種資產一組 entity / DTO / resolver / Table / DetailBtn）也很一致，適合 AI 照著擴充。

做法

  1. 先建 AI 的開發環境（3–4 天，最划算的投入）
    • 修好 jest、用 docker 起本機 Postgres、補齊 .env.main.local 與 ormconfig.json 範本，讓 agent 能自己跑測試與 migration。
    • codegen 改成可讀本機 schema 或 schema 檔。
    • 把 digiquick-bond-cmtat-vault-changes.md 拆成每個模組的任務規格，每項附驗收條件（輸入、狀態轉換、錯誤路徑）。
    • 每個 repo 補 CLAUDE.md：分層、命名、path alias、GenerateAssetType.md 規則、Next.js 12 / MUI v5 的版本限制。
  2. 契約先行：M1 的冷錢包 mock server 照指南 v0.7 先做好，GraphQL schema 先定。之後前後端 agent 依契約並行，不互等。
  3. 並行開發：每個模組一個 git worktree、一個 agent，產出程式碼加單元測試；人審過才合併，每個 PR 先跑自動 code review。依原排期的相依順序推進，M6、M7、M8 的前後端可同時做。
  4. 人必須負責的部分
    • 簽章與 webhook 驗證、權限（含 asset(id) 漏洞）。
    • 款到才 mint、逾期註銷等涉及金額與鏈上狀態的流程。
    • 既有資料的 migration。
    • 對 Aegis dev 環境的端到端驗證與溝通。
    • 改動說明第 10 節的待確認事項：AI 只能先依預設值實作並標記，不能代為決定。
  5. 回歸安全網：一開始就讓 AI 為其他 8 種資產補一組基本的 resolver 測試，確保 bond 改動不影響既有資產（已計入 M12）。

AI 模式特有的風險

  • 審查跟不上：AI 一天能產出數個模組，人審不完就會累積技術債與隱性 bug。審查產能決定整體速度。
  • 冷錢包 API 仍是草稿：指南 v0.7 欄位一改，mock server 與 client 都要跟著改。AI 改得快，但每次都要重新驗證。
  • 框架版本舊：Next.js 12、MUI v5、TypeORM 舊版寫法，AI 可能寫成新版 API，要在 CLAUDE.md 明確限制並以 lint、build 把關。
  • 安全與金流程式碼：AI 產出的簽章、權限、交割邏輯看起來正確但可能有邊界錯誤，必須人工逐行審查並有對應測試。
